# Day 03 — 2026.10.07 (수)

## [오늘 목표]
- 지금까지 한 작업을 미션 요구사항과 대조해 빠진 부분 점검·보완
- **단계 2 (Crop)**: 학습 이미지의 검은 여백을 잘라내면 지름길 단서가 사라지고 학습·테스트 차이가 줄어드는지 확인 (가설 H1)
- 2.5단계: Crop 후 학습·테스트 밝기 차이를 다시 재서 단계 3(밝기 대응)의 강도 결정

## [선택한 방법]
- **문서 점검**: 미션 참조사항과 대조 → Mission 0 문서가 파일로 없던 것 발견·작성(`Mission0_Strategy.md`), 데일리 로그에 미션 체크·Reflection 섹션 추가, 오래된 내용(마감일, 평가 지표 칸, Baseline 한계 ⑤) 수정
- **Crop 동작 확인**: 학습 정상 2장·폐렴 2장(여백이 큰 `train_3582`, 기울어진 `train_5089` 포함)·테스트 2장에 Crop을 적용해 원본과 나란히 비교
- **밝기 재측정**: Crop 전/후 학습(600장)·테스트(624장) 평균 밝기 비교
- **E2 학습**: E1b 설정(ResNet18 전체 미세조정, lr 1e-4, 5 epochs)에 **Crop만 추가** → Crop의 효과만 분리

## [선택 이유]
- EDA(검은 영역 정상 17.6% vs 폐렴 31.5%)와 Baseline 진단(테스트 이미지는 여백 없음)에서 Crop이 **지름길 차단 + 학습·테스트 형태 통일**이라는 두 가지 근거를 가짐
- 학습 전에 Crop 결과를 눈으로 확인한 이유: 폐 영역까지 잘려나가면 실험 자체가 의미 없어지기 때문
- 밝기를 다시 잰 이유: 기존 밝기 차이(88.7 vs 121.0)가 실제 밝기 차이인지, 검은 여백(밝기 0)이 평균을 끌어내린 것인지 구분해야 단계 3의 방향을 정할 수 있음
- E1b에서 Crop **하나만** 바꾼 이유: 여러 개를 동시에 바꾸면 성능 변화가 무엇 때문인지 알 수 없음

## [결과]

| 실험 | Val Acc | Val AUC | Sens | Spec | FN | FP | 테스트 확률 중앙값 | 테스트 정상 예측 비율 | 리더보드 |
|---|---|---|---|---|---|---|---|---|---|
| E1b (Before) | 0.9799 | 0.9979 | 0.977 | 0.989 | 18 | 3 | 0.982 | 0.386 | 0.9407 |
| **E2 (After, + Crop)** | **0.9875** | **0.9988** | 0.986 | **0.993** | **11** | **2** | 1.000 | 0.284 | **0.9022** |

- **Crop 동작**: 여백 제거 정상, 폐 잘림 없음 / 기울어진 이미지의 모서리 삼각형은 남음(한계)
- **밝기 재측정**: 차이 33.4 → **1.1 (97% 감소)** → 밝기 차이의 대부분은 검은 여백 때문이었음 → 단계 3은 가볍게
- **E2**: 검증 지표는 전부 개선, 그러나 테스트 정상 예측 비율 0.284(실제 약 0.375)·확률 중앙값 1.000 → 정상을 폐렴으로 과하게 판정하는 경고 신호
- **리더보드 0.9407 → 0.9022 (−3.85%p)**, 검증-리더보드 격차 3.9%p → **8.5%p** → 간접 지표로 예측한 상한(약 0.91)과 일치 → **가설 H1 기각**
- **새 가설 H1'**: Crop 후 폐렴 이미지는 넓적(224×143)하고 정상은 정사각형에 가까움(221×187) → Resize 시 폐렴만 세로로 늘어남 → "늘어난 이미지 = 폐렴"이라는 새 지름길 → 넓적한 테스트 이미지가 폐렴으로 기울어짐

- **가로세로 비율 진단**: Crop 후 학습 정상 1.19 / 학습 폐렴 1.47 / 테스트 1.46 → **가설 H1' 확인** (테스트가 폐렴과 같은 비율이라 폐렴으로 기울어짐)
- **근본 원인**: 원본 비율 차이 → 패딩 양 차이 → 검은 영역·밝기 차이. 여러 현상이 하나의 원인에서 나옴

- **재현성 확인**: 새 노트북에서 Run all → E1a·E1b·E2 결과가 이전 실행과 **완전히 동일** (필수 규칙 2 확인)
- **E2b (Crop + 고정 비율 1.3)**: Val AUC 0.9967, FN 24·FP 6, 테스트 정상 예측 비율 **0.296** → 쏠림 해결 안 됨 → **리더보드 0.8990** (E1b 대비 −4.2%p) → 가설 H1b 기각
- **방향 전환**: Crop 계열(E2, E2b) 모두 테스트 쏠림 → Crop 미채택, **E1b로 복귀**해 학습 방식 전략(가중치 손실, 학습 설정)으로 진행

## [달성도]
- **가설 기준: 실패** — Crop은 리더보드를 올리지 못하고 오히려 3.85%p 떨어뜨림 (가설 H1 기각)
- **과정 기준: 성공 (약 70%)** — 밝기 문제의 원인 규명(97%가 여백), 리더보드 하락을 제출 전에 예측, 새 지름길 가설(H1') 도출까지 진행. 비율 진단으로 원인 일부 확인, E2b도 실패했지만 재현성 확인과 방향 전환 근거 확보

## [인사이트]
- **측정 결과에 따라 계획을 바꿨음** — 밝기 문제를 본격적으로 다루려 했지만, 재측정해 보니 차이의 97%가 검은 여백 때문이었음. 측정 없이 CLAHE를 적용했다면 거의 존재하지 않는 문제에 시간을 썼을 것
- **검증 점수가 좋아져도 테스트에서는 나빠질 수 있음** — 검증셋은 학습셋과 분포가 같아서 새로 생긴 지름길을 잡아내지 못함. 테스트 확률 중앙값·정상 예측 비율 같은 간접 지표가 이상 신호를 먼저 알려줌
- **한 문제를 고치면 숨어 있던 문제가 드러날 수 있음** — 검은 여백을 없앴더니 여백이 가리고 있던 가로세로 비율 차이가 드러남. 여백은 "넓적한 원본을 정사각형으로 맞추려고 덧댄 것"이었을 가능성 → 여백 차이와 비율 차이는 같은 원인의 다른 모습일 수 있음
- **같은 방향 실험이 연속으로 실패하면 방향을 바꿔야 한다** — 비율이라는 원인을 찾았지만 고쳐도 해결되지 않았음. Crop 계열을 고집하기보다 가장 좋았던 E1b로 돌아가 다른 축(학습 방식)을 실험하기로 판단
- **재현성은 직접 다시 돌려봐야 확인된다** — Seed를 고정했다고 끝이 아니라, 처음부터 Run all로 같은 숫자가 나오는지 확인해서 규칙 준수를 증명함
- **증상이 아니라 원인을 찾아야 한다** — 검은 영역, 밝기, 비율 차이가 각각 다른 문제인 줄 알았지만 모두 '원본 가로세로 비율'이라는 하나의 원인에서 나왔음
- **실패한 실험도 원인을 좁혀준다** — E2의 하락 덕분에 "여백만이 문제가 아니라 원본 비율 차이가 근본 원인일 수 있다"는 더 깊은 가설로 나아감
- **테스트 간접 지표(정상 예측 비율)로 리더보드 하락을 미리 예측할 수 있었음** — 제출 횟수를 아끼고 실험 방향을 빨리 판단하는 데 유용

**💡 Reflection Questions (오늘 답할 수 있는 것)**
- **실험 결과가 예상과 다른 경우 그 이유는 무엇인가요?**
  → Crop으로 검증 성능은 올랐지만(AUC 0.9988) 리더보드는 0.9407 → 0.9022로 떨어졌고, 테스트에서 폐렴 쪽으로 과하게 기울었음. Crop 후 폐렴 이미지가 정상보다 넓적해서 Resize 때 더 많이 늘어나고, 모델이 이 "늘어남"을 새 단서로 배운 것으로 보임. 비율 진단 결과 학습 정상 1.19 / 학습 폐렴 1.47 / 테스트 1.46으로 **가설 H1' 확인**. 다만 비율을 통일한 E2b도 쏠림이 해결되지 않아, 비율만으로는 전부 설명되지 않음.
- **Train/Validation 데이터 분리는 어떻게 수행했나요?**
  → 02_Baseline에서 층화 분할(8:2, Seed 42)한 결과를 `split_train.csv` / `split_valid.csv`로 저장하고, 모든 실험이 이 파일을 불러 써서 같은 검증셋으로 비교함.
- **데이터 누수(Data Leakage)는 발생하지 않았나요?**
  → 검증셋은 에폭별 성능 확인과 최고 에폭 선택에만 쓰고 가중치 업데이트에는 쓰지 않음. 테스트 이미지는 예측과 관찰(크기·밝기·비율)에만 썼고, 정규화 값·임계값 등 설정에는 사용하지 않음. 단, 원본 데이터의 환자 단위 분리는 파일명이 익명화되어 불가능하다는 한계가 있음.
- **실험을 체계적으로 관리하기 위한 방법은?**
  → `run_experiment` 함수 하나로 모든 실험을 같은 파이프라인으로 돌리고, 설정(cfg)만 바꿈. 결과는 `results.csv`에 자동 누적, 모델·제출 파일은 실험 이름(E1a, E2…)으로 저장. 한 번에 하나씩만 바꿔 효과를 분리.
