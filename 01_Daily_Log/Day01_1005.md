## [선택한 방법]
- **문제 정의 및 지표 설정**: 정상/폐렴 이진 분류, 모델 평가는 ROC-AUC + Sensitivity / Specificity
- **EDA**: 클래스 분포, 파일 정렬 순서, 이미지 크기·채널, 샘플 이미지 육안 비교
- **추가 검증**: 샘플에서 관찰한 "폐렴 이미지의 검은 여백"이 데이터 전체에서도 나타나는지 수치로 확인 (1차: 밝기 5 이하 픽셀 비율, 2차: 줄 전체가 검은 행·열 비율)
- **Baseline 분석**: 공식 SimpleCNN 코드를 구조·설정별로 분해하여 한계 정리
- **작업 환경**: Colab(T4 GPU), 데이터·모델은 구글 드라이브, 코드·기록은 로컬 Git 폴더

## [선택 이유]
- 불균형 데이터에서는 Accuracy가 성능을 과대평가할 수 있어, 모델의 실제 구분 능력은 AUC와 민감도·특이도로 판단하기로 함
- 개선 전략을 근거 있게 고르려면 데이터 특성과 Baseline의 한계를 먼저 알아야 한다고 판단
- 샘플 10장의 인상만으로는 결론을 낼 수 없어, 관찰을 수치로 검증하는 단계를 추가함
- 로컬 PC에서 GPU 환경을 구성하는 대신 바로 GPU를 쓸 수 있는 Colab을 선택하여 실험 시간 확보

## [결과]
> 오늘은 모델 학습 전 단계라 Before/After 성능 대신 분석 결과를 기록

- **클래스 분포**: 정상 1,341장(25.7%) / 폐렴 3,875장(74.3%) → 불균형 2.89배
  - 전부 "폐렴"으로 예측해도 Accuracy 74.3% → Accuracy만으로는 판단이 어려움을 확인
- **파일 정렬**: `train_0001~1341` 정상, `train_1342~5216` 폐렴으로 완전 정렬 → 셔플·층화 분할 필수
- **이미지 속성**: 전체 224×224, 흑백 1채널(`L`)
- **검은 영역 검증**
  - 1차: 정상 24.7% vs 폐렴 35.6%
  - 2차: 정상 17.6% vs 폐렴 31.5%
  - → 폐렴 이미지는 몸이 화면에서 차지하는 비율이 일관되게 작음 → **Crop 전략 후보 도출**
- **Baseline 한계 6가지 도출**: 검증셋 부재, 불균형 미고려, 해상도 손실(224→128), 작은 모델·짧은 학습, 임계값 고정, 재현성 장치 부재
- **대회 규칙 확인**: 공식 평가 지표 Accuracy, 1일 10회 제출, 외부·원본 데이터 및 테스트 데이터 학습 사용 금지, 마감 10/18

## [인사이트]
- 1차 검증에서 "완전 검정 = 패딩"이라고 가정했으나, X-ray에서는 **몸 바깥 공기도 완전 검정**으로 찍혀 패딩과 구분되지 않았음 → 가정이 틀리면 측정 방식부터 다시 설계해야 한다는 것을 배움
- 측정 대상을 완벽히 분리하지 못했어도, 두 번의 측정이 같은 방향의 차이를 보여 "폐렴과 무관한 특징이 클래스와 연관되어 있다"는 결론은 일관됨
- 성능이 높게 나와도 근거가 폐 병변인지 **Grad-CAM으로 반드시 확인**해야 함 (Grad-CAM 논문의 '의사/간호사 분류' 편향 사례와 같은 구조)
- 대회 지표(Accuracy)와 모델 평가 지표(AUC)는 역할이 다름 → 대회 점수는 Accuracy로 확인하되 모델 개선은 AUC·민감도·특이도로 판단
- 원본 데이터는 한 환자가 여러 장 촬영된 경우가 있으나 파일명이 익명화되어 환자 단위 분리 불가 → 데이터 누수 가능성을 한계로 기록할 것
- Colab 런타임이 재시작되면 이전 셀 결과가 사라짐 → 셀 순서를 지키고 "모두 실행"으로 재현성 확인하는 습관 필요

**💡 Reflection Questions**
- **전체 접근 흐름은 어떻게 설계했나요?**
  → EDA → Baseline 재현·평가 → 문제점 도출 → 개선 전략 설계 → 한 번에 하나씩 바꾸는 단계별 실험 → Baseline 비교 → 오답 분석 → Grad-CAM 해석 → 결과 데이터·Risk Level 정의 순서로 설계함. 데이터와 Baseline의 한계를 먼저 알아야 근거 있는 전략을 고를 수 있다고 판단했기 때문.
- **왜 해당 평가 지표를 선택했나요?**
  → 대회 공식 지표는 Accuracy지만, 폐렴이 74.3%라 전부 폐렴으로 찍어도 Accuracy가 74.3%가 나옴. 그래서 모델 개선 판단은 임계값과 무관하게 구분 능력을 보는 AUC와, 실수의 종류를 보여주는 민감도·특이도로 하고, Accuracy는 리더보드 확인용으로 씀.
- **Baseline 이전에 어떤 문제를 예상했나요?**
  → ① 클래스 불균형으로 다수 클래스(폐렴) 편향 ② 데이터가 적어 처음부터 학습하면 과적합 ③ 검증셋이 없어 성능을 신뢰하기 어려움.
- **어떤 전략을 먼저 적용할 계획이며, 그 이유는?**
  → 사전학습 모델(ResNet18) + 원본 224 해상도. Baseline의 모델 용량·해상도 한계가 가장 기본적인 제약이라 이후 전략들의 공통 출발점으로 삼기 위함.
- **실험 결과를 어떻게 검증할 것인가요?**
  → train을 층화 분할(8:2)해 검증셋을 만들고 그 분할을 파일로 고정, Seed 42 고정, 모든 실험을 같은 검증셋으로 평가. 검증 점수와 리더보드 점수를 함께 기록해 격차까지 확인.
