# Day 02 — 2026.10.06 (화)

## [오늘 목표]
- 공식 Baseline(SimpleCNN)을 재현하고 성능을 측정할 수 있는 상태로 만들기
- Baseline 성능을 기록하고 문제점·개선 가설을 도출하여 Mission 1 마무리
- 개선 전략을 설계하고(Mission 2) 첫 실험으로 사전학습 모델과 Fine-tuning 방식 비교

## [선택한 방법]
- **공식 Baseline 재현**: 모델·학습 설정(128×128 흑백, SimpleCNN, CrossEntropyLoss, Adam 1e-3, 2 epochs)은 그대로 유지
- **평가 장치 추가**
  - 층화 분할(Stratified Split)로 검증셋 8:2 구성 → `split_train.csv`, `split_valid.csv`로 저장
  - Seed 고정 + DataLoader 셔플 순서 고정 (재현성)
  - 검증 지표: Accuracy, AUC, Sensitivity, Specificity, F1, Confusion Matrix
  - 모델 저장 후 재로드 검증
- **진단**: 검증 vs 테스트 예측 확률 분포, 테스트 이미지 크기·밝기 비교
- **대회 규칙 확인**: 공식 평가 지표 Accuracy, 1일 10회 제출
- **Mission 2 설계**: 전략 S1 Crop / S2a CLAHE / S2b 밝기·대비 증강 / S3 클래스 가중치 손실 / S4 학습 설정, 한 번에 하나씩 바꾸는 단계별 실험 설계
- **단계 1 실험**: ImageNet 사전학습 ResNet18(224×224)로 Fine-tuning 방식 비교
  - E1a: 사전학습 층 고정, 분류층만 학습 (lr 1e-3)
  - E1b: 전체 층 미세조정 (lr 1e-4)

## [선택 이유]
- 공식 Baseline에는 검증셋이 없어 train loss 외에 성능을 확인할 방법이 없었음 → 검증셋을 만들어야 이후 개선 실험을 비교할 수 있음
- "Baseline vs 개선 모델"을 공정하게 비교하려면 모델·학습 설정은 바꾸지 않고 평가 장치만 추가해야 한다고 판단
- 분할을 파일로 저장하여 이후 모든 실험이 같은 검증셋으로 평가되도록 함
- 대회 지표는 Accuracy지만, 불균형 데이터에서는 Accuracy만으로 판단하기 어려워 AUC·민감도·특이도를 함께 기록

## [결과]

| 구분 | Accuracy | AUC | Sensitivity | Specificity | F1 |
|---|---|---|---|---|---|
| (기준) 전부 폐렴 예측 | 0.7433 (검증) / 0.625 (리더보드) | - | 1.0 | 0.0 | - |
| **Baseline (검증셋)** | **0.9454** | **0.9832** | 0.9433 | 0.9515 | 0.9625 |
| **Baseline (리더보드)** | 0.7468 | - | - | - | - |
| E1a 분류층만 학습 (검증) | 0.9646 | 0.9944 | 0.987 | 0.899 | - |
| E1a (리더보드) | 0.8333 | - | - | - | - |
| **E1b 전체 미세조정 (검증)** | **0.9799** | **0.9979** | 0.977 | 0.989 | - |
| **E1b (리더보드)** | **0.9407** | - | - | - | - |

- 에폭별 Val AUC: 0.9758 → 0.9832 (2 epochs에서도 상승 중)
- 검증셋 오류: 놓친 폐렴(FN) 44명, 오진한 정상(FP) 13명
- **검증 vs 테스트 차이**
  - 폐렴 확률 중앙값: 검증 0.979 → 테스트 0.503
  - 정상 예측 비율: 검증 28.6% → 테스트 49.7%
  - 테스트 이미지는 원본 크기(1112×736 등) 그대로, 평균 밝기 121.0 (학습 88.7)
- **도출한 문제점**: ① 학습·테스트 분포 차이로 검증 성능이 실제 성능을 대변하지 못함 ② 테스트에서 False Negative 증가 가능성 ③ 지름길 학습 위험 ④ 학습 부족·모델 용량 한계
- **개선 가설**: H1 Crop / H2 밝기·대비 증강 / H3 사전학습 모델 + 224 해상도 / H4 클래스 가중치 손실
- **단계 1 결과**: 리더보드 0.7468 → **0.9407** (+19.4%p), 검증-리더보드 격차 19.9%p → 13.1%p(E1a) → **3.9%p(E1b)**
  - 테스트 확률 중앙값 0.503(E0) → 0.592(E1a) → **0.982(E1b)** → 전체 미세조정에서 분포 차이가 크게 완화됨
  - → E2부터 기본 설정은 E1b(전체 미세조정)

## [인사이트]
- **학습 이미지와 테스트 이미지의 성질이 다르다는 것을 발견함** — 학습 이미지만 224×224로 가공되어 있고 테스트 이미지는 원본 크기·더 밝은 상태 → 검증 점수가 높아도 테스트에서는 성능이 떨어질 수 있음
- EDA 단계에서 "지름길 차단"을 위해 떠올린 Crop 전략에 **"학습·테스트 형태 차이 줄이기"라는 두 번째 근거**가 생김
- 불균형 때문에 특이도가 낮을 것으로 예상했지만, 검증셋에서는 오히려 놓친 폐렴(44명)이 더 많았음 → 예상은 실제 결과로 확인해야 함
- 대회 지표(Accuracy)와 모델 평가 지표(AUC)는 역할이 다름 — 리더보드는 Accuracy로 확인하되, 모델 개선 판단은 AUC·민감도·특이도로 함
- **시행착오**: 학습 후 모델 생성 셀을 다시 실행해 **학습 안 된 모델이 저장·제출됨** (첫 제출 0.625, 테스트 확률이 모두 0.51~0.54, 재로드 모델 AUC 0.38)
  - 저장 후 다시 불러와 검증하는 코드 덕분에 실수를 발견함
  - 노트북은 "세션 다시 시작 및 모두 실행"으로 순서대로 실행해야 함을 배움
- 테스트 비율을 이용한 계산은 결과 분석에만 쓰고, 설정 조정에는 쓰지 않기로 함 (규칙 준수)
- **같은 사전학습 모델이라도 Fine-tuning 방식에 따라 결과가 크게 다름** — 분류층만 학습(E1a)은 검증 0.96인데 리더보드 0.83으로 무너졌고, 전체 미세조정(E1b)은 0.94를 유지함 → ImageNet과 X-ray처럼 성격이 다른 데이터에는 특징 자체를 조정해야 함
- 검증 점수만 보면 E1a도 좋아 보였지만, **테스트 확률 중앙값**이 낮으면 리더보드에서 무너진다는 신호였음 → 리더보드에 내기 전 확인할 수 있는 유용한 지표
- 비율이 맞아도(정상 예측 0.386 ≈ 실제 0.375) 오류가 양방향으로 상쇄될 수 있으므로, 비율만으로 성능을 판단하면 안 됨

**💡 Reflection Questions**
- **Baseline 모델은 어떤 구조이며, 이미지를 어떻게 처리하나요?**
  → 흑백 1채널 이미지를 128×128로 줄이고 0~1 텐서로 변환(정규화·증강 없음). 모델은 Conv(1→16)–ReLU–MaxPool, Conv(16→32)–ReLU–MaxPool 2층으로 특징을 뽑은 뒤 펼쳐서(32,768개) Linear로 정상/폐렴 점수 2개를 냄. 학습 가능한 가중치 약 7만 개, 사전학습 없이 2 epochs.
- **현재 평가 지표는 무엇이며, 왜 적절한가요? Accuracy 대신 AUC를 쓰는 이유는?**
  → 대회는 Accuracy로 채점하지만, 불균형 데이터에서는 전부 폐렴으로 찍어도 74.3%가 나와 모델 능력을 가리지 못함. AUC는 "폐렴 이미지에 정상 이미지보다 높은 확률을 주는가"를 임계값과 무관하게 보므로 찍기로는 높아지지 않음. 그래서 모델 판단은 AUC + 민감도·특이도로, 리더보드는 Accuracy로 확인함.
- **데이터가 불균형한 경우 어떤 문제가 발생하나요?**
  → 다수 클래스 편향, Accuracy 과대평가, 소수 클래스(정상) 학습 부족. 이번 테스트셋은 정상 비율(약 37.5%)이 학습셋(25.7%)보다 높아, 폐렴 쪽으로 기운 모델은 리더보드에서 더 손해를 봄.
- **현재 데이터는 불균형 상태인가요? 어떻게 확인했나요?**
  → 불균형(폐렴 2.89배). `value_counts()`로 확인, 층화 분할 후에도 train·valid 모두 25.7 : 74.3 유지됨을 출력으로 확인.
- **Baseline 모델의 가장 큰 한계는 무엇인가요?**
  → **학습·테스트 분포 차이로 검증 성능이 실제 성능을 대변하지 못하는 것.** 학습 이미지는 224×224 가공본(검은 여백 포함, 밝기 88.7), 테스트는 원본 크기(여백 없음, 밝기 121.0). 검증 Acc 0.9454인데 리더보드 0.7468로 약 20%p 하락, 테스트 폐렴 확률 중앙값이 0.503으로 모델이 헷갈려함.
- **해당 문제를 해결하기 위한 개선 방향은?**
  → H1 검은 여백 Crop(지름길 차단 + 학습·테스트 형태 통일), H2 밝기 차이 대응(CLAHE 또는 밝기·대비 증강), H3 사전학습 모델 + 224 해상도, H4 클래스 가중치 손실.
